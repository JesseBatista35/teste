Causa raiz identificada: o package-lock.json do projeto estava desatualizado em relação ao package.json. O package.json já exigia @angular/cdk, @angular/material, @angular/animations e @angular/platform-browser-dynamic todos na versão 20.3.27, além de @caixa/sdsc-angular na 0.1.18, mas o lockfile ainda trazia versões antigas resolvidas (@angular/cdk em 20.2.14, @angular/material em 20.2.14, @angular/animations em 20.1.8, @angular/platform-browser-dynamic em 20.0.7 e @caixa/sdsc-angular em 0.1.17), nunca regenerado após a atualização das dependências. Essa divergência impedia o npm de determinar de forma unívoca a versão instalada de @angular/cdk, gerando o erro ERESOLVE unable to resolve dependency tree na fase npm install da pipeline.

Encaminhamento: causa e correção identificadas e repassadas ao time de desenvolvimento do siasc-novo. Cabe ao time de dev remover o package-lock.json e a pasta node_modules localmente, rodar npm install para regenerar o lockfile alinhado às versões pinadas no package.json (20.3.27 para os pacotes @angular/* e 0.1.18 para @caixa/sdsc-angular), e commitar o lockfile atualizado no repositório.

Resultado esperado: com o lockfile alinhado ao package.json, a instalação passará a resolver corretamente os peer dependencies sem necessidade de flags de bypass (--legacy-peer-deps ou --force), e a fase npm install da pipeline voltará a concluir normalmente.
